# Read-only audit — `companion_scripts/repair_companion_services.sh`

**Scope.** Entire 132-line target was inspected, plus its immediate contracts: `installer_common.sh`, all five templates, four service writers, shared config/runtime entry points, repair documentation, prior checkpoint (`6c3420a^`), and focused tests. No project files, Git configuration, packages, network, hardware, firmware, or live services were changed. Temporary unit trees and stub `systemctl` commands only were used.

## Findings

| Severity | Lines | Finding |
|---|---:|---|
| High | 41–58, 77–90 | **Repair corrects only `WorkingDirectory`; it leaves a second, current systemd path-format defect: quoted `EnvironmentFile=`.** `installer_common.sh:31–39` labels its formatter suitable for `EnvironmentFile`, and all core/camera installers use it. In a disposable unit on systemd 255, `EnvironmentFile="/tmp/companion space/config.txt"` emitted `EnvironmentFile= path is not absolute, ignoring`; `EnvironmentFile=/tmp/companion\ space/config.txt` verified cleanly. The repair’s narrow transform intentionally retains the quoted `EnvironmentFile`, then `systemd-analyze verify` exits 0 despite that warning, so it reports success and persists a unit whose file is ignored. Python services may still find the same file through `Environment=QUIVER_ENV_FILE=...`, but that does **not** populate shell-expanded settings in `tailscale-funnel.service`; its `${TAILSCALE_FUNNEL_PORT}`, `${GO2RTC_API_HOST}`, and `${GO2RTC_API_PORT}` therefore remain unset. This directly contradicts the docs’ claim that `EnvironmentFile` is active at start. **Fix:** add a directive-specific EnvironmentFile formatter in the shared installer (literal absolute path with systemd escaping, e.g. escaped spaces and doubled `%`, not shell-style double quotes); regenerate current installers/templates. Extend this repair tool only if it is explicitly intended to repair this earlier emitted form, with a guarded `EnvironmentFile` transform and backups. |
| Medium | 83–90 | **Validation can announce “passed” while an installed drop-in still has a fatal service setting.** The script validates staged main units and checks only `result.returncode`. In an isolated `quiver-hub-client.service.d/override.conf` containing `WorkingDirectory=relative`, `systemd-analyze verify` printed the bad-setting diagnostic but returned 0; the script replaced the main stale unit, ran `daemon-reload`, and printed “Validation passed.” A direct repro showed `--recursive-errors=yes` returns nonzero for the same drop-in. **Fix:** call `systemd-analyze verify --recursive-errors=yes --man=no …` (with an explicit compatibility policy/fallback if supporting an older systemd) and add a drop-in regression. This also prevents claiming that all effective unit definitions were validated when only their diagnostics were emitted. |
| Medium | 30–34, 61–72 | **The generic `go2rtc.service` and `tailscale-funnel.service` names can modify or block repair because there is no Quiver ownership check.** The candidate list includes both generic system-wide service names and accepts any regular file at those paths. A disposable unrelated `go2rtc.service` with a quoted absolute `WorkingDirectory` was modified, backed up, and followed by `daemon-reload`. Conversely, an unrelated invalid `go2rtc.service` blocked a read-only repair of an otherwise repairable Quiver Hub unit. **Fix:** identify camera-generated units using a stable Quiver marker/description and refuse ambiguous non-Quiver units, or require an explicit opt-in for those two generic names. Keep the five project-specific service names as the default repair scope. |
| Medium | 98–127 | **A failed `systemctl daemon-reload` leaves repaired files on disk but no successful retry occurs on the next run.** In an isolated root-mode repro where only stubbed `daemon-reload` returned 73, the script atomically replaced the unit and made its backup, then exited with an uncaught `CalledProcessError`. A second successful invocation saw `changed == []`, did not run `daemon-reload`, and reported `repaired 0`; systemd could continue using the old loaded definition. **Fix:** catch reload failure and clearly state that units were written but not loaded; retry reload on non-check runs even when zero files changed, or persist a root-owned pending-reload marker and retry until it succeeds. Add this failure/retry test. |
| Low | 54–55 | **Malformed quoted input produces a Python traceback rather than an operator-facing failure.** A relative quoted value correctly refuses modification, but the `ValueError` is uncaught and prints a traceback. This is fail-closed and does not write units, but is needlessly hard to diagnose during a field repair. **Fix:** catch `ValueError` around `corrected()` and exit with the unit path plus a concise, actionable error; retain nonzero status and no-write behavior. |

## Confirmed behavior / non-findings

- **Original failure is confirmed:** a disposable unit with `WorkingDirectory="/tmp/companion 100% ready"` produced systemd 255’s `WorkingDirectory= path is not absolute`; after the target removed only outer quotes, real `systemd-analyze verify` passed. The focused regression suite passed all 5 tests.
- The transform is deliberately narrow: it changes only a quoted `WorkingDirectory` inside `[Service]`, preserves `%%`, preserves other quoting, refuses symlink candidate files and unrendered templates, stages every selected unit before base-file replacement, preserves metadata, creates non-overwritten backups, and is idempotent after a successful reload.
- Quoted/backslash-containing directory paths were repaired in temporary units and accepted by the local parser. The target requires only Bash, Python standard library modules, `systemd-analyze`, and (for apply) `systemctl`; its embedded Python is portable to Python 3.13.
- The repair script neither imports companion runtime modules nor invokes async functions; it has no firmware/network/package-install/service-start operation. Its only apply-side system action is `systemctl daemon-reload`. Hardware and flight-controller behavior were **not** tested.
- Stale-suite scope was checked against `6c3420a^`: the candidate names cover the pre-fix Hub, telemetry, Logs/OTA, camera, go2rtc, and Funnel writers. Current source templates use literal `WorkingDirectory`; the still-current `EnvironmentFile` quoting flaw is a separate formatter contract issue.
